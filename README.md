# 复扫雷 Complexweeper

一个可直接在浏览器中玩的复数扫雷游戏，支持电脑和手机。

雷有四种：+1、−1、+i、−i。格子显示周围八格雷之和的模长，例如 +1 和 +i 得到 √2。正负雷互相抵消，因此 **0 与空白不同**：0 周围存在雷，空白周围没有雷，只有空白会连片展开。

翻开所有非雷格子就胜利。第一次翻开的格子及其八个邻格不会有雷。可选初级、中级、高级或自定义尺寸和四种雷的精确数量。

## 操作

- 左键翻开；右键循环旗帜：空 → +1 → −1 → +i → −i → 空。
- 手机使用「翻开 / 标旗 / 问号 / 展开」切换点击操作；较宽的盘面可横向滚动。
- 中键或左右键同时按住会预览邻格，松手尝试展开周围未标旗的格子。单独左键点击已翻开的格子不会展开。要求旗帜总数等于真实邻雷数量，且实虚数量符合真实比例或其倒数。旗帜位置错误仍可能踩雷。
- 「问号」模式点击格子，或将指针停在格子上、聚焦格子后按单引号，添加问号标记。新标记颜色按蓝、蓝、紫、紫、棕、棕、绿、绿循环；重复标记同一格按蓝、紫、棕、绿切换颜色，不改变下一对的顺序。Shift 点击或 Shift+引号清除。标记可叠加在已翻开格或旗帜上，不影响扫雷规则，也不会启动计时。
- 旗帜保护未翻开的格子，需将旗循环回空才能翻开。
- 四种雷的计数在首次翻开后显示，数值为对应雷总数减去该类旗帜数。

- F2、「开局」或人脸按钮重开；支持 100%、200%、300% 盘面缩放。
- 「最高分纪录」查看三档标准尺寸和雷数的最好用时，胜利刷新纪录时自动弹窗。最短计分为 1 秒，保存在当前浏览器的 localStorage 中；自定义局若尺寸和雷数恰好与标准档一致也参与计分。
- 「玩法与操作」和「关于」打开相应对话框。「退出」停止本局并冻结计时，点击新一局可恢复游戏；浏览器页面保持打开。
- 计时按秒显示，上限为 9999 秒。自定义表单从当前局预填，随机类型局的雷数尽量均匀分到四种类型。「按合计均分」按当前编辑的雷数总和重新均分，合计为 0 时使用 99，均分合计上限为 999。

标准档每颗雷的四种类型各以 25% 概率独立生成；自定义按指定数量生成。生成采用与原生版相同的 Mulberry32、Fisher–Yates 洗牌与首次点击安全区，已用原生 Zig 参考盘面核对相同种子的随机盘面和自定义盘面。

## 复制盘面

选择 CSV 或纯文本（制表符分隔），点击「复制盘面」。只复制当前可见信息，不包含未翻开的雷位置。浏览器无法访问剪贴板时，会提供可选择的文本供手动复制。

| 标记                       | 含义                           |
| -------------------------- | ------------------------------ |
| `?`                        | 未翻开                         |
| `_`                        | 已翻开的空白                   |
| `0`、`√2` 等               | 已翻开的数字，保留界面显示形式 |
| `F+1`、`F−1`、`F+i`、`F−i` | 对应类型旗帜                   |
| `XF…`                      | 失败后可见的错误旗帜           |
| `M+1`、`M−1`、`M+i`、`M−i` | 失败后可见的雷                 |

问号标记在可见内容后附加 `{?A}`（蓝色）、`{?B}`（紫色）、`{?C}`（棕色）或 `{?D}`（绿色），例如未翻开且有蓝色问号的格子为 `?{?A}`。

每行对应一行盘面；负号使用 Unicode `−`。

## 分享对局

点击「分享对局」复制链接，接收者打开后可从当前盘面继续。链接使用版本化 URL 片段，包含种子、盘面配置、首次翻开位置、步数、已翻开格及其数值、四种旗帜、问号颜色与下一对的顺序、已用时间与胜负或结束状态。兼容旧版分享链接。未开始的预标旗或问号盘面也可分享；结束的盘面保持结束。打开已完成的分享局不会写入本地纪录。剪贴板不可用时提供手动复制文本。

相同种子、配置和首次翻开位置会生成相同盘面。链接是复制瞬间的快照，不会同步后续操作；继续玩的计时从快照时间累加。分享链接包含重建完整雷区的信息，可用于复盘，也可以被解码看到隐藏雷区。格式版本不受支持或内容不一致时显示错误并保留当前游戏。链接无需服务器存储，支持 GitHub Pages 子路径。

## 本地运行

需要 Node.js 24 和 pnpm 11.25.0。

```sh
pnpm install
pnpm dev
```

终端会显示开发地址。`pnpm test` 检查核心规则，`pnpm build` 进行类型检查并生成静态站点到 `dist/`，`pnpm preview` 预览构建结果。

## GitHub Pages

在仓库 Settings → Pages 中将 Source 设为 **GitHub Actions**。`.github/workflows/pages.yml` 会在 `main` 或 `feat/web-game` 分支推送时构建并部署，也支持手动运行。初次网页迁移可从 `feat/web-game` 部署，后续主分支更新会继续部署。

Vite 使用相对资源路径，支持 GitHub Pages 的仓库子路径；不需要后端服务。网页沿用原生版的经典灰色布局与 `素材/图集.png` 图像素材，按原始尺寸支持 100%、200%、300% 缩放。
